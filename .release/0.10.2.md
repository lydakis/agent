# Agent 0.10.2

Since 0.10.1: protocol 85 -> 97, schema 106 -> 108. Restart the daemon after upgrading.

## Security
- Sandbox and approval hardening (security fixes; details in an advisory after release) (#1197).

## Daemon
- Every daemon tool now runs as a script's step, except the ones Codex keeps out of its scripts (wait, history, web_search and the agent tools). shell with detach or tty, and write_stdin, run as direct calls (protocol 86) (#1135).
- `exec` hands its call back with what the script has said so far once it has run for its `yield_time_ms` (30 s by default), or at once on `yield_control()`, and the script keeps running until `wait` collects the rest, as Codex's exec does (#1134).
- A code-mode script's step writes (`take_call`, `approve_step`, `step_result`, `tool_result`, `yield_call`, a client's `answer`) no longer hold the run loop. On a disk where every sync takes 300 ms, approvals, inspect and bots p50 drop from about 2.7 s to under 3 ms. At 10,000 agents and 32 to 200 windows, step writes held the loop 11 to 28 ms in 20 s, down from 1.8 to 4.3 s (#1163).
- A parked turn's claim no longer holds the run loop when it resumes (#1177).
- One selector picks messages and follows alike, and what memory said is one read (protocol 87) (#1161).
- `close` takes a selector, so one call closes many agents, and every close stops what the bot is running (protocol 89) (#1181).
- A live event is encoded once for all its followers, not once per follower (#1173).
- `bots` takes `names` (1 to 256), so a client reads only the rows of agents it heard move, and an event a pattern's follow delivers names the pattern as `following` (protocol 90) (#1180).
- Closing an agent ends the follows it held, as deleting does, except the ones posting in a commons thread made, so news no longer wakes a closed agent (#1179).
- The sky feed and the lookout's per-subscriber mailbox count their queued bytes against the connection's budget, so a slow reader can no longer grow an unbounded queue (#1169).
- A provider ramp finds its parked turns by turn, not by scanning them all, so a 429 storm no longer costs a scan per turn, and retained streams are packed before the store's writer (#1168).
- A bot's instructions move out of its row (schema 107), so listing agents never reads them. At 10,000 bots a full listing's store time drops from 129 ms (#1148).
- `agent stats` lists each open connection: its program, its label, and its own counts and times (#1149).
- Anthropic requests leave out blank text blocks, as Pi does (#1147).
- The reviewer judges a round even when it can't read back an earlier file change, as Codex does, and a step's 2 KB preview names the files it changes (#1155). When the reviewer hands a call to the person, its note names the command and gives the reviewer's reason (#1156).
- A refused history argument is named, a lifted approval says who holds it, and fork's answer leaves out the instructions (#1159).
- Looking up a new agent's workspace no longer runs on the shared request path (#1145). Per-bot sockets still work when the daemon's address is long (#1144). Client file updates are safe with concurrent writers (#1136). macOS subprocess errors are passed on (#1139).
- Agents can replace a note still waiting in another agent's line (send_message replaces, run --replaces) (protocol 91) (#1200).
- The history tool takes no `limit`: a turn reads in 64 KiB pages through `offset`, and a search pages by `before` (#1210).
- A profile names the sandbox its agent starts in, and spawn_agent and `--profile` honor it. Agents get allow rules through always allow, and the sonny-config skill says so (#1202).
- A message or note for a busy agent never moves its running call to the background. It waits until the call ends or yields on its own time, as Codex does; a declared `lift` is now `yields` (protocol 92) (#1203).
- An automation is judged by its parts, each as the tool it amounts to: a check is a shell step in the agent's sandbox, waking another agent is a send_message step, starting a task is a start_task step. One that only wakes the agent that adds it, or removing its own, asks no one (protocol 93) (#1207).
- `[speeds]` and `[context_windows]` in config.toml now travel with each agent as settings, so an edit reaches an agent's next turn with no daemon restart. The daemon's `--speeds` and `--context-window` flags are gone (protocol 94) (#1208).
- A bot's `namespace` setting groups the agents its `list_agents` lists and names what `spawn_agent` makes, in place of reading its name up to the first dot. A bot inherits its creator's namespace, Sonny sets each agent's to its project, and existing bots keep their first-dot group (schema 108, protocol 96) (#1220).
- Linux builds (static musl, x86_64 and aarch64) allocate with jemalloc, with Codex's settings, and compile their C code with Zig as Codex's do (#1158, #1194; #1193 kept aarch64 on musl's allocator until then).

## Sonny
- Code mode: the tool host keeps Codex's one bound. Up to 2,048 scripts can be alive, each on its own thread, and one more is refused at once. There's no separate cap on how many run (#1167).
- Code mode: a tool host call claims a process place only when one is free. Each agent with a call waiting holds one fair reservation, calls that run no process go at once, and side chats are charged by their verified record (#1186).
- Margin: it scrolls, and every note is drawn whole (#1146). It lists this agent's own tasks that need you (#1160).
- Agents and projects show their titles beside their names (#1157).
- An agent with no title takes its first message's first line, cut at a word to 60 characters, and `start_task` no longer takes a title (#1212).
- Projects: `/projects`, or `←` with nothing typed, shows every project where the conversation was, each with its most pressing agent's mark and its counts, a project inside another's folder hung under it, and projects idle seven days folded away. `enter` goes to the picked project's lead (#1215).
- Arrows between agents and projects: with nothing typed, `→` gives the keys to the pane, `alt+←`/`alt+→` step the window through the project's agents as the pane lists them, and `←` at a pane's first page gives the keys back (#1216).
- /usage shows Tasks in place of Time by agent: how many tasks finished without you against the period before, by length and by role. `usage` takes `names` and `until_ms` (protocol 97) (#1214).
- The footer shows `← ? N` for what needs you in other projects (a click opens Projects), and `alt+n` goes to the next agent that needs you. Every window of a store shares one follow for it (#1217).
- A project's agents show above the margin. In a task's window, /status, /background, /usage, /audit and the footer scope to the project's lead (#1205).
- Nothing on the status row runs past the conversation's column (#1154).
- /status draws at once and fills in as it reads, and closed agents leave its listing (#1206).
- /status keeps the card it laid out and draws it again when nothing under it changed, so a key that changes nothing on the card no longer lays out every row. With 32 windows on 10,000 agents, the lead's CPU drops from 31% to 17% and its key p50 from 4.4 to 0.9 ms (#1225).
- A window lists its project once and then follows it, reading only the agents it hears move, where it listed every agent every 3 s (#1180).
- A window's count rebuilds only the agents that moved, and keeps its listing typed. With 100 windows in one 10,000-agent project, windows CPU drops from 277% to 147%, memory from 10.1 to 4.6 GiB, and key p99 from 79 to 20 ms (#1195).
- A window's count does less again, building only the rows that moved. With 32 windows on 10,000 agents, windows CPU drops from 110% to 78% and memory from 1.30 to 1.08 GiB (#1218).
- Keys never wait on the daemon: the window reads and handles keys on its own, one event at a time (#1166).
- A reconnect's catching up is read beside the window's loop, so keys never wait on it (#1184).
- A window waits for keys without waking when nothing is happening (#1176).
- Sonny reads Markdown as CommonMark and GFM with pulldown-cmark, streaming by finished blocks like Codex: setext headings, `~~~` fences, escapes, entities, reference links, footnotes and hard breaks now draw correctly, and previews are about 5x cheaper (#1198).
- Diagrams, formulas, pages and pictures draw on their own thread beside the window's loop, so keys never wait on them, and what it takes to redraw a picture is kept on disk beside it, not in memory (#1170, fixes #1178).
- The lookout sees two writes of one follow file within one file-time step, and a source's watched command files likewise: a change is judged by device, inode, size and times, as git's stat data (#1213).
- The lookout passes a source's JSON line without `text` through to subscribers whole (#1204).
- A task that needs the person opens no tab, and the flash stays (#1153).
- Tasks end an automation run that finds nothing with an empty reply, so their lead is not woken for it. A question's reminder no longer asks the agent for a line on what it holds up, and a question's options say what you will see or get if you pick each one (#1201).
- A follow's due digest delivers everything it held, in notes one after another (#1152).
- /background and the automations listing say when the scheduler isn't running (#1150).
- A link's browser picks up the person's new sign-ins (#1151).
- Cached pictures are redrawn after an upgrade, and the cache lives in a folder of the user's own (#1143).
- Faster with many agents: the page near the view is found by halving (#1171), an event for one agent looks at none of another's steps (#1172), and the scheduler looks only at the triggers it may start and writes only what changed (#1175).
- A lead takes its folder's instructions as a window opens, not again at every idle point, so its prompt cache holds across its turns. A busy lead's requests that break the cache drop from 12 in 125 to 1 in 124 (#1211).
- The workflow skill has an agent make one piece first when the pieces are alike (#1199).
- The sonny-config skill teaches `[speeds]` (#1162). Monochrome rendering is honored (#1139).

## Install
- The installer runs the new release before it replaces the installed one, and swaps links by rename (#1142). Sonny is reported current only after a successful Homebrew listing (#1138).

## Bench and tests
- `bench/ends.py` scans the process table once per sample, divides CPU by the time actually measured, and reports PSS beside RSS. A run fails when a request is refused or a turn doesn't complete (#1163). Benchmark outputs are kept, and incomplete results are rejected (#1137). The scripted demos report their actual results (#1141).
- Test fixes: socket addresses no longer depend on checkout depth (#1140); a Sonny test fixed after #1156 (#1164); a flaky server-test cleanup that turned main's CI red (#1174); the slow-page key test looks for its placeholder row in any frame (#1187); key-loop tests bound a key by the answer held back, not milliseconds (#1196).
- Docs: measurements of the window that lists its project once (#1189), of this release against 0.10.1 (#1190), and of the allocators compared for the static Linux build (#1221). Version 0.10.2 (#1188).

## Measured
Against 0.10.1 with `bench/ends.py` on the final tree (548534a), a 4-core Linux machine, glibc builds (so without jemalloc), two rounds each, with the store's one-time migrations marked done on both sides.
- Low end (10 agents, one window): turns hold (p50 48 ms on both), key p99 1.2 to 2.1 ms against 2.0 to 2.5 ms. A quiet window wakes about 6x less (26/s to 4.5/s). Idle memory is a little higher: window PSS +1 MiB, daemon +0.7 MiB.
- High end (10,000 agents, 30 busy, 32 windows on one project): scripts finished +45% and turns +9% in the same 20 s. Windows CPU 6.8% to 5.3% and their wakeups down 31%. Key p99 11 to 20 ms down to 12 to 15 ms, and the worst key 18 to 30 ms down to 20 to 27 ms; key p50 1.5 to 1.9 ms. The daemon spends 10 more CPU points (124% to 134%) on the extra work, and each window holds about 0.25 MiB more PSS.
