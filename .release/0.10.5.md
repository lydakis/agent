# Agent 0.10.5

Since 0.10.4: protocol 100 (unchanged), schema 112 -> 113. Stores move forward automatically when the daemon starts, and `libexec/store_down.py` takes one back. Restart the daemon and Sonny's windows after upgrading.

**Upgrading with a linked machine:** upgrade the linked machine (the Mac you run `sonny link` on) first. From this release on, it upgrades the host it links to as it connects, so one upgrade covers both (#1322). Then run `sonny link <box>` once on the Mac, so dropped files and Ctrl+V pictures reach the box over SSH (#1321).

## Daemon
- A turn at another effort than its bot's (Sonny's boost) keeps the cache: the request keeps the bot's own effort, and a small item ahead of the turn's prompt sets the effort from there (Claude's mid-conversation `output_config`, OpenAI's `configuration_update` from GPT-6). Not on Bedrock yet. The prompt node keeps its turn's effort (schema 113) (#1312).
- Providers: GPT-6.2's instructions go as the first `developer` message so they are cached again; cache writes are counted (GPT-5.6 and later); Bedrock's cached reads stay off the pacer's quota for OpenAI models; `cache_ttl` takes `12h` (OpenAI, API key); GPT-6.2 Astra and Sol take fast and ultrafast, and a reply served `fast` (OpenAI's new name for `priority`) logs as fast (#1310).
- `agent tool` runs one `shell`, `read`, `write`, `edit` or `apply_patch` call in the sandbox `agent sandbox` builds, read only unless `--writable` names folders and with no network unless `--network` (#1330).
- `spawn_agent` and `send_message` take `schema`, a JSON Schema the reply of the turn they start must follow (the provider's strict structured output). A `send_message` with a schema waits for a turn of its own instead of steering (#1329).

## Sonny
- Agents run their shell and file tools on a linked machine, inside that machine's sandbox: a code-mode step names `machine`, asked here first as any call. `[sonny.links.NAME] writable` and `network` say what the box's agents may do there (#1330).
- Linked machines keep one release: as a link connects, the end behind upgrades, driven by the linked machine. A failed upgrade is not retried for the same pair; `upgrade = false` under `[sonny.links.NAME]` turns it off; `sonny link` shows both builds while they differ (#1322).
- Any dropped file reaches the agent. Pictures in HEIC, HEIF, AVIF, JXL, TIFF and BMP are converted on a Mac; other files go as their path; a path from the Mac over SSH is fetched through the link into `~/.agent/sonny/dropped/`, and Ctrl+V over SSH takes the Mac's clipboard picture (#1321).
- Keys are never held: letters already waiting are typed before the next frame (#1313); pictures and long code files are made ready beside the typing (#1315); a long paste of code sent is colored off the key loop (#1325); Find and a long line of code still coming stop growing with length (#1314); an embedded program that stops reading, the waiting line and the sky stop costing per key, window or link (#1316).
- `exec` builds its tools once and reuses them until a listing changes, and rereads `~/.agent/config.toml` only after it was written (#1307). A tool call names its caller in its invocation, never the process's variables (#1311).
- Boards: `pause`, the commons tool's sixth `do`, keeps work that isn't ready from being offered, and a closed agent's work threads end with it (#1319). A `done` records its author's branch and commit, and whoever takes work needing it hears them (#1327).
- A long run of folded calls copies none of their rows while shut (#1328), and a selection stays while rows under it are drawn again (#1332).
- Layout: every message keeps the conversation's width and the band pads it one column at each end (#1308) (#1323); the footer spans the conversation's width (#1326); a list over the composer keeps the conversation's two columns (#1333); the space after a word that fills a composer row stays on it (#1331).
- A window that opened before its terminal answered asks its colors again, so its band is no longer gray (#1306).
