# Agent 0.10.4

Since 0.10.3: protocol 99 -> 100, schema 111 -> 112. Stores move forward automatically when the daemon starts, and `libexec/store_down.py` takes one back. Restart the daemon and Sonny's windows after upgrading (protocol 100).

## Daemon
- A turn the daemon was running when it crashed or was killed goes on at the next start instead of ending `process_interrupted`, as Pi Durable continues a run. A model call in flight is asked again after the first backoff; a tool call with no result is answered `process_interrupted` and never run again; a turn whose final reply was already recorded ends `completed`. Each turn may be continued 5 times in a row with no progress (`--restarts` / `[daemon] restarts`, `0` always; a bot's `max_restarts` stands over it) (schema 112) (#1275).
- A stop, a pause or a crash keeps the calls of a round that had not started, and their approval requests, instead of answering them "did not run". A call a client was answering (a declared tool, a script, an ask) waits on for its answer across the restart (#1283).
- When a provider says the context is too long (`provider_context_full`, from typed codes only), the turn summarizes and sends the call once more instead of ending, as Codex and Pi Durable do. A second refusal ends the turn (#1273).
- No bound on a whole reply: a long reply ends at the model's own output cap. One SSE event or WebSocket message is bounded at 64 MiB, Codex's number (#1269).
- `read`, `edit` and `write` lose the caps Codex and Pi don't share: `read` pages any file a line at a time, and `edit` and `write` take files of any size (#1277).
- `send_message` between agents always steers, as Codex's agent mail does: it joins the recipient's running turn at its next step, or starts one. `delivery` is refused (#1272).
- `spawn_agent` takes no `tools` and a fork no `allow`: a helper has its caller's tools, and only a profile a person writes narrows them, as in Codex, Claude Code and Pi. The CLI's `--tools` can also pick client tools (#1290).
- Fork-and-delete is cheaper. A small agent is deleted in one store job instead of three, and `fork` takes its first message (`submit`), committed with the fork in one job (protocol 100). Sonny's next-message guess, haiku and reviewer copies use it: a throwaway copy costs 6 store commits instead of 11, and its call under load drops from 110 to 83 ms at the median (#1304).
- The daemon's socket is bound owner-only in a private folder and renamed into place, instead of changing the process's umask around the bind (#1284).

## Sonny
- /commons says work: what is on a board is a thread, and its kind is work. A board with only plain threads shows its name and age, a plain thread on a board names its board, its last writer is a link, a row of work gives up labels, age and "for" before its title when short of room, and work its maker took back says "canceled it" (#1301).
- Work that waits on other work says `waiting` in every answer and read, as the board's listing does, not `open` (#1302).
- A question goes up the lineage: every agent above the one that asked shows it, with or without a multiplexer, and it survives closing and reopening windows. Approvals held below go up the same way (#1298).
- While the person is away (`[sonny] away_minutes`, 30 by default, `0` never), leads raise only decisions; once the person is back, each lead gives one catch-up (#1285).
- Commons boards rethink: the `board` tool folds into the commons tool; `start_task` takes `agents` and `board`; posts on a board steer the agents they concern; the tool host checks each turn end instead of a lease; and `for` invites live agents when work opens. Any follow takes `quiet` (tells once after a span with nothing heard) beside `filter`, `digest` and `steer`; boards set it from `[sonny] hold_quiet` (#1293).
- An `exec` script the tool host was running when it stopped (a crash, an upgrade) runs on after the restart from its journal, as Pi Durable's code mode does: recorded results come back in order and are not run again (#1292).
- The `ask` tool is simpler: 6 fields instead of 9, `one_way` instead of `if_unanswered`/`wait_minutes`, no `command` (a step only the person can take is an ask with no options) (#1282).
- A lead gets a failed task or helper going again, and tells the person when a start fails twice or a fix needs them (#1297).
- `start_task` with a profile runs the profile's model, as `spawn_agent` does (#1286).
- A retrying turn's row says why, such as `Rate limited` or `Retrying: connection lost` (#1288).
- A pick never answers a question that was already answered (#1274).
- `/switch` rows lead with the name, a task's title muted after it (#1291).
- The find field has one place, the row under the title, in every pane view and Projects (#1294).
- A follow's `test` marks where a busy source's kept history starts late (`dropped_before`), so missing hours no longer read as gaps (#1287).
- The tool host reads each agent once at start for both tools and config, and stops re-declaring every agent's tools at each start: at 10,000 agents that was 20,000 `inspect`s and 10,000 `configure`s per start (#1271) (#1276).
- The reviewer renews its lease from the moment it holds it, so a slow start or a backlog no longer loses it (#1270).
